# ラインペイント

画像を、昔のパソコンのお絵かきと同じ手順で描く「絵データ」に変換するツールです。線を引き、線で閉じた所を塗り、市松模様のタイルで塗り重ねていく様子を、そのままの速さで再生できます。

<p align="center"><img src="docs/images/sample1_normal.gif" width="640" alt="描画の様子"></p>

```
1. 線を引く       絵全体の輪郭を、線画として引き切る
2. ベタ塗り       線で閉じた範囲を、単色で塗りつぶす
3. タイル塗り     市松模様の領域を、ベタの上からタイルで塗り直す
4. 線の引き直し   塗りの都合で仮の色で引いた線を、本来の色で引き直す
```

- 使える色は、8 色と、そのうち 2 色を市松に並べたタイル（28 通り）。合わせて 36 色です。
- 解像度は 640×200（縦長ドット）、160×144、任意の大きさから選べます。
- 8 色はデジタル 8 色か DB8。使う色を 1〜8 色に絞れます（1 色なら線画）。
- データ容量の上限を KB で指定できます。収まるように、線を多角形に間引きます。
- PC-8801 のパレット切り替えを使った描き方（デジタルパレット）も再現できます。
- 描いていく様子を GIF アニメで保存できます。

インストールは不要です。HTML ファイルをブラウザで開くだけで動きます（ネットにもつながりません）。

## 見本

元の画像を変換して、描いていく様子を GIF アニメにしたものです。

| 元の画像 | 通常の見せ方 | デジタルパレット |
|---|---|---|
| <img src="docs/images/sample1_source.png" width="260"> | <img src="docs/images/sample1_normal.gif" width="260"> | <img src="docs/images/sample1_palette.gif" width="260"> |
| <img src="docs/images/sample2_source.png" width="260"> | <img src="docs/images/sample2_normal.gif" width="260"> | <img src="docs/images/sample2_palette.gif" width="260"> |

- **通常の見せ方**では、絵の色のまま、線を引いて塗っていきます。
- **デジタルパレット**では、描いている色だけを 1 色（上の段は青、下の段は黄）で見せ、ほかは背景の色（上の段は黒、下の段は青）に沈めます。全部描き終えると、パレットを本来の色に戻して、絵が一度に現れます。できあがる絵は、通常の見せ方と同じです。

## 使い方

### 1. 変換画面を開く

`lp_converter.html` をブラウザ（Chrome・Edge・Firefox など）で開きます。

![変換画面](docs/images/converter.png)

左が設定、右が結果です。設定を変えると、すぐに変換し直します。

### 2. 画像を読み込む

「ここへ画像をドロップ」に画像をドロップするか、クリックして選びます。画面のどこにドロップしても読み込めます。

読み込むと変換が始まり、右の「描画再生」で描いていく様子が流れます。

### 3. 画面と色を決める

「画面」の欄で、できあがりの形を決めます。

| 欄 | 内容 |
|---|---|
| 解像度 | 640×200（縦長ドット・16:10）/ 160×144 / 任意 |
| 合わせ方 | 画像の縦横比が違うときの扱い。中央で切り抜き / 全体を収める（余白は白）/ 引き伸ばす |
| パレット | デジタル 8 色 / DB8 |
| 使う色 | 色見本をクリックして、使う色を選んだり外したりします。「全色」「白黒」で一度に切り替えられます。1 色にすると線画になります |
| 紙の色 | 描き始めの画面の色。自動では、使う色でいちばん明るい色です |

### 4. 結果を見比べる

右上のタブで、見るものを切り替えます。

| タブ | 内容 |
|---|---|
| 描画再生 | 絵データを実際に描かせた様子。下の「一時停止」「最初から」「最後まで」「速さ」「拡大」で操作します |
| 完成の絵 | 描き終えたときの絵 |
| 線画（工程1の後） | 線だけを引き終えたところ |
| 減色のみ | 画像を 36 色に置き換えただけの絵。線や塗りに直す前の、目標の絵です |
| 元画像（縮小後） | 解像度に縮めて、色補正をかけた画像 |

その下の表に、線分や塗りの回数、描画時間、データ量が出ます。「検証のずれ」が 0 なら、保存したデータは完成の絵どおりに描けます。

### 5. 仕上がりを調整する

| やりたいこと | 欄 |
|---|---|
| 色味を変える | 「原画の色補正」で赤・緑・青・彩度・明るさ・コントラストを調整します。動かしている間は下書きを、手を止めると正式な結果を出します |
| 輪郭の線を変える | 「線」の欄。イラストは「暗い線」、写真は「明暗の段差」が向いています |
| 細かい所をまとめる | 「塗り」の「最小領域」「境目をならす」を上げます |
| データを小さくする | 「データ容量」で上限を指定します。線を多角形に間引いて収めます |
| 減色しただけの絵どおりに描く | 「仕上げと見せ方」の「『減色のみ』の絵を完成形にする」を有効にします。データは増えます |
| デジタルパレットで描く | 「仕上げと見せ方」の「見せ方」をデジタルパレットにし、「描いている色」「それ以外の色」を選びます |

困ったときの目安:

- **網点や縞が線になってしまう**: 「細かい模様（網点・縞）を線にしない」を有効にします（既定で有効）。それでも残るときは「しきい値」を上げます。
- **輪郭の線が途切れる**: 「隙間を閉じる」を上げるか、「しきい値」を下げます。
- **市松模様（タイル）が多すぎる**: 「市松の抑制」を上げると、単色が選ばれやすくなります。
- **色がくすむ、または暗い**: 「原画の色補正」で彩度や明るさを上げます。
- **線が直線的すぎる**: 「線の単純化」を下げます。0 でドットどおりです。

### 6. 保存する

結果の下のボタンで保存します。

| ボタン | 内容 |
|---|---|
| picture.js を保存 | 絵データを `picture.js` として保存します |
| データをコピー | 絵データをクリップボードにコピーします |
| GIF アニメで保存 | 描いていく様子を `picture.gif` として保存します。速さは再生欄の「速さ」に従います。「GIF の大きさ」「コマ」（1 秒あたりのコマ数）も選べます |

640×200 の絵は、GIF では縦を 2 倍にして、見た目どおりの 640×400 で出します。

### 7. 再生する

保存した `picture.js` を `lp_player.html` と同じフォルダに置き、`lp_player.html` を開くと再生します。ほかの絵データは「別の絵」から選べます。

再生画面では、速さ・拡大と、見せ方（絵データの指定どおり / 通常 / デジタルパレット）を選べます。速さ「×1」は、元の `main.js` と同じ拍子です（線は毎秒 600 本、塗りは毎秒およそ 750 本の走査線）。

## 変換のしくみ

### 1. 下ごしらえ

- 画像を目標の解像度に縮めます。面積平均を自前で行います（ブラウザ任せだと網点がモアレになるため）。
- 「原画の色補正」を、縮めた直後の画像にかけます（下の「原画の色補正」）。
- 「細かい網点・ディザを均す」が有効なとき、RGB コード値のまま、最低 2 ドット幅で平均します。候補の市松を「コード値の平均」で見積もっているので、入力の網点も同じ物差しで均します（揃えないと、白＋黄の網点が白と判定されるなどの食い違いが出ます）。
- 輪郭を残す平滑化（バイラテラルフィルタ）をかけ、各ドットを最寄りの候補色（単色 8 ＋ 市松 28）に割り当てます。
- 主線は、周囲より暗い細い線（ブラックハット変換）か、明暗の段差（Sobel）で抽出し、1 ドット幅に細くします。線が密集している所は、網点などの模様とみなして捨てます。画面のいちばん外側の 1 ドットの枠は、主線にしません（枠に沿った偽の線が出るため）。

### 2. 線の網

1. **線にするドットを決める。** 主線のドットと、「右か下のドットと色が違うドット」（色の境目）を線にします。上下左右に隣り合う色の違う 2 ドットは、必ずどちらかが線になります。
2. **細くする。** 1 ドット幅の骨格にします（Zhang-Suen 法のあと、余分なドットをつながり方を変えない範囲で除く）。画面の端のドットは削りません。
3. **鎖に分ける。** 分岐点・端点から次の分岐点・端点までを 1 本の鎖にします。鎖は両端の分岐点のドットを共有します。
4. **色を決める。** 主線は主線の色。色の境目は、隣の色に溶け込む色にします（下の表）。
5. **頂点を間引く。** 鎖の両端は動かさないので、間引いても線どうしのつながりは保たれます。
6. **描き戻す。** エンジンと同じ線分で描いたものを、正式な線とします。領域は、ここから求め直します。

色の境目の線の色:

| 両側の色 | 線の色 |
|---|---|
| 単色と単色 | 線が多く乗っている側の色（境目が 1 ドット動くだけ） |
| 単色と市松 | 単色の側の色（完全に溶け込む） |
| 市松と市松 | 共通の色があればそれ。なければ暗い方の色 |

線は紙の色では引けません（塗りが線で止まらなくなるため）。溶け込ませたい色が紙の色のときは、別の色で引いておき、単色の紙の色に溶け込ませる線だけ、最後に紙の色で引き直します（工程 4）。

### 3. 塗り

線で閉じた範囲（線でないドットの、上下左右につながる塊）ごとに塗ります。色は、その範囲のドットの多数決で決めます。

- 除外色は、その範囲に接している線の色すべてです。
- **単色の領域**: ベタ塗りだけ。紙の色の領域は、何もしません。
- **市松の領域**: ベタ → タイル。ベタの色は、タイルの 2 色のうち周りの線の色でない方（明るい方を優先）。片方が紙の色のとき、または両方が周りの線の色のときは、ベタを省いて直接タイルで塗ります。
- 種点は領域の重心にいちばん近いドットで、そこから上下へ広がって塗られます。
- 順番は大きい領域から。背景（画面の端にいちばん長く接する領域）は最後です。

### 4. 検証

保存する文字列そのものを読み直してエンジンで描かせ、完成の絵とドット単位で比べます。画面の「検証のずれ」が 0 なら、絵データは完成の絵どおりに描けています。

「減色のみとの差」は、線の間引きや縁の色のために、減色しただけの絵と違っているドットの割合です。塗りの漏れなど大きな崩れがあると、この値が跳ね上がります。

## 「減色のみ」の絵を完成形にする

通常の完成の絵は、線の間引きと、線を隣の色に溶け込ませる都合で、「減色のみ」の絵と 1% ほど違います。「『減色のみ』の絵を完成形にする」を有効にすると、次のようにして差を 0 にします。

- 線は間引かず、ドットどおりに引きます（「線の単純化」は効かなくなります）。
- 工程 1〜4 を終えた画面と「減色のみ」の絵を比べ、違っているドットを、工程 4 の続きとして、正しい色の短い線で打ち直します。
- 粗さ（容量の上限）は、線を多角形にする代わりに、「減色のみ」の絵そのものを簡単にします（境目をならす回数を増やし、小さい領域を吸収し、短い主線を捨て、似た色の領域をまとめる）。粗くしても、その粗さでの「減色のみ」の絵とは一致します。

データ量は増えます（見本の絵で 7.1KB → 11.3KB、打ち直し 879 ドット）。1 色の線画では効きません。

## デジタルパレットの見せ方

PC-8801 のカラーパレットの切り替えを使った描き方の再現です。画面に書き込む色番号は通常の見せ方とまったく同じで、色番号をどの色で表示するか（パレット）だけを変えます。できあがる絵は変わりません。

1. 画面は紙の色の番号で塗りつぶされていますが、パレットを全部黒にしているので、黒く見えます。
2. 線や塗りを始めるとき、これから描く色番号のパレットだけを青 (0,0,1) にし、ほかは全部黒 (0,0,0) にします。色番号が変わると、それまで見えていた部分は消えます。
3. 前に使った色番号でもう一度描くときは、その番号が青になるので、前に描いた部分も一緒に現れます。
4. タイル塗りは、2 色のうち片方だけが青なので、青と黒の市松に見えます。青にするのは、直前のベタ塗りに使った色番号です（ベタを省いたタイルは、紙の色でない方）。
5. 全部描き終えたら、全部黒のまま 0.5 秒（30 コマ）待ち、パレットを既定に戻して絵を現します。

青と黒は既定の見せ色で、変換画面で「描いている色」「それ以外の色」を、PC-8801 のデジタル 8 色からそれぞれ選べます（使っている 8 色のパレットが DB8 でも、見せ色はデジタル 8 色から選びます。パレットに登録するのはハードウェアの色なので）。2 色を同じにすると、描いている間は何も見えません（画面に注意が出ます）。

変換画面の「見せ方」で選ぶと、絵データに `"drawMode": "palette"` と `"palColors": ["描いている色", "それ以外の色"]` が入ります。エンジンは `new LP3.Engine(絵データ, 'normal' | 'palette', [描いている色, それ以外の色])` で、絵データの指定を上書きできます（`palColors` がない絵データは青と黒）。待ち時間は `LP3.PAL_REVEAL_HOLD`（絵を現す前）と `LP3.PAL_SWITCH_HOLD`（色番号を切り替えるたび。既定 0）で変えられます。

## 原画の色補正

赤・緑・青・彩度・明るさ・コントラストを、それぞれ −100〜+100 で調整します。縮めた画像にかけるので、元の画像の大きさに関わらず速く、目標の解像度で見たとおりに効きます。

かける順番は、赤緑青の倍率 → 明るさ → コントラスト（中間の明るさを軸に）→ 彩度（−100 で白黒）です。

スライダーを動かしている間は、簡易の変換（輪郭を残す平滑化を 1 回だけにした「減色のみ」）をその場で表示し、手を止めて 0.2 秒ほどで正式の変換に置き換わります。簡易の表示は、正式の結果と 5% ほど違うことがあります。

## GIF アニメ

変換画面の「GIF アニメで保存」で、描画の様子を GIF アニメ（`picture.gif`）にして保存します。

- 速さは、再生欄の「速さ」に従います。見せ方（通常／デジタルパレットと見せ色）は、絵データの指定どおりです。
- 「GIF の大きさ」の自動は、横 320 ドット未満の絵（160×144 など）を 2 倍、それ以外を等倍にします。縦長ドット（640×200）は縦を 2 倍にして、見た目どおりの縦横比（640×400）で出します。
- 「コマ」は 1 秒あたりのコマ数です（10・20・25・50）。
- 描き終えた絵を 2 秒見せてから、最初に戻って繰り返します。
- 前のコマから変わった部分だけを書き出すので、見本の絵（×1、20 コマ/秒）で約 51KB、作成は 0.3 秒ほどです。デジタルパレットは色番号を切り替えるたびに画面全体の色が変わるので、大きくなります（同じ絵で約 280KB）。

`LP3.makeGif(絵データ, { speed, fps, zoom, mode, palColors, holdSec, loop, onProgress })` は `lp_gif.js` にあり、GIF の中身（`Uint8Array`）を返します。外部のライブラリは使っていません。

## 設定

| 欄 | 既定 | 内容 |
|---|---|---|
| 解像度 | 640×200 | 640×200（縦長ドット）/ 160×144 / 任意（正方形ドット） |
| 使う色 | 8 色 | 色見本をクリックして選ぶ。1 色にすると線画になる |
| 紙の色 | 自動 | 描き始めの画面の色。自動は、使う色でいちばん明るい色。主線の色とぶつかるときは、主線を紙といちばん明るさの違う色にする（紙を黒にすると白い線になる） |
| 原画の色補正 | すべて 0 | 赤・緑・青・彩度・明るさ・コントラスト。−100〜+100 |
| 主線を抽出する | 有効 | 切ると、色の境目だけで線画を作る |
| 線の単純化 | 0.7 | 頂点を間引く許容誤差（ドット）。0 でドットどおり |
| 隙間を閉じる | 4 | 主線の切れ目をつなぐ長さ。塗りの漏れとは関係ない（見た目のため） |
| 最小領域 | 16 | これより小さい領域は隣の色に吸収する |
| 境目をならす | 1 | 3×3 の多数決の回数。境目のギザギザを減らす |
| 塗る順番 | 領域ごと | 領域ごとにベタ → タイル / ベタを全部塗ってからタイルを全部 |
| 上限を指定する | なし | データ容量の上限（KB）。収まるいちばん細かい粗さを自動で探す |
| 粗さ | 0 | 〜0.7 は頂点を間引いて形を多角形にする。0.7〜 は飾りの線を捨て、似た色の領域をまとめる |
| 圧縮して保存する | 有効 | 折れ線と塗りの並びを詰めて保存する。切ると、読める形で出す |
| 「減色のみ」の絵を完成形にする | 無効 | 完成の絵を「減色のみ」の絵とドット単位で一致させる |
| 見せ方 | 通常 | 通常（描く色のまま見せる）/ デジタルパレット（1 色で描いて、最後に色を現す） |
| 描いている色 / それ以外の色 | 青 / 黒 | デジタルパレットの見せ色。デジタル 8 色から選ぶ |

## 絵データの形式

```js
window.LP_PICTURE = {
  "format": "line_painter", "version": 3,
  "width": 640, "height": 200, "pixelAspect": 2,
  "paletteName": "digital8", "palette": ["#000000", ...],
  "colors": [0,1,2,3,4,5,6,7],   // 使うと指定した色（情報用）
  "clear": 7,                     // 紙の色
  "drawMode": "palette",          // デジタルパレットの見せ方のときだけ入る
  "palColors": ["#0000ff", "#000000"],  // その見せ色（描いている色、それ以外の色）。drawMode と一緒に入る
  "ops": [ ... ]
};
```

| 命令 | 内容 |
|---|---|
| `["S", n]` | 工程の印。1 線を引く / 2 ベタ塗り / 3 タイル塗り / 4 線の引き直し |
| `["L", 色, [x0,y0,x1,y1,...], ...]` | 折れ線 |
| `["D", 色, "base64"]` | 折れ線（圧縮。座標の差分を可変長整数で符号化） |
| `["P", 模様, 除外色, [x,y,...]]` | 塗りつぶし。模様は色番号の 2 次元配列。除外色のドットで止まる |
| `["R", "base64"]` | 塗りの並び（圧縮）。領域ごとに「ベタ → タイル」を続けて行う |

塗りつぶしは 4 連結で、今回の塗りでまだ塗っておらず、除外色でもないドットを塗ります。模様の中に除外色が入っていても構いません。

## 改造するときの注意

次の条件で「塗りが漏れない」「完成の絵どおりに描ける」が成り立っています。

1. **線分は `LP3.linePixels` の一つだけで描く。** エンジンと、変換の描き戻しが同じ関数を使う。必ず始点と終点を通り、向きによらず同じドットになる。
2. **領域は、描き戻した線から求め直す。** 間引く前の線から求めた領域を使ってはいけない。
3. **線は紙の色で引かない。** 塗りは「紙の色のままのドット」を進むので、紙の色の線は壁にならない。
4. **除外色は、その領域に接している線の色すべて。** ベタの色は除外色に入れない（入れるとタイルで塗り直せない）。
5. **細線化で画面の端のドットを削らない。** 端まで届いている線の先が 1 ドットでも削れると、そこから漏れる。
6. **塗りは 4 連結、線は 8 連結。** 8 連結で閉じた線は、4 連結の塗りを止める。
7. **鎖の両端（分岐点）は、間引きで動かさない。**
8. **デジタルパレットは、表示のパレットだけを変える。** 画面（色番号）に書き込む内容を見せ方で変えてはいけない。

## 既知の制約

- 市松の領域どうしの境目は、線が単色で 1 ドット残ります（共通の色がなければ暗い方の色）。
- 主線を抽出すると、髪の房などが線で細かく仕切られるので、領域の数とデータ量が増えます（見本の絵で、主線なしなら 4.8KB）。
- 粗さ 0.7 を超えると、目などの細部が消えます。さらに上げると、領域をまとめすぎて色が変わります。
- 変換中は画面が固まります（640×200 で約 0.5 秒、容量指定時は 1〜1.8 秒）。
- 「減色のみ」を完成形にすると、打ち直しの点が最後にぱらぱらと打たれます。元の描き方にはない動きです。
- デジタルパレットでは、紙の色の番号で描く部分（線の引き直しなど）は、画面全体が「描いている色」になります（紙の色の番号がその色になるため）。
- 再生画面の「見せ方」で絵データの指定を上書きしたときも、見せ色は絵データの `palColors`（なければ青と黒）を使います。再生画面では見せ色を選べません。
- 再生の速さは経過時間で合わせているので、元の `main.js` と完全に同じコマ割りではありません。
